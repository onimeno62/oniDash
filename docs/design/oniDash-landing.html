Made for real collections

Less file management. More actually using your library.

oniDash is built around the boring-but-important parts of a personal media collection: indexing, metadata, search, progress, playback and a UI you will want to come back to.

⌕

One search layer

Search across your library with shared full-text indexing and ranked results instead of separate silos for every catalogue.

◈

Useful metadata

Extract metadata automatically, edit it when needed, and keep catalogue information useful when files move or drives go offline.

↯

Safe indexing

Recursive scanning, background jobs, identity-based upserts and missing-file handling are designed for large local collections.

♫

A proper music workspace

Artists, albums, tracks, playlists, favourites, history, queues, artwork, metadata editing and ranged audio playback.

▣

Purpose-built catalogues

Movies, manga and books get experiences suited to their own workflows while sharing the same application foundation.

⌂

Local by design

Your catalogue is backed by local storage and SQLite. Your media remains on the machine and folders you control.

The experience

One application. A different rhythm for every medium.

The shell stays familiar while each catalogue gets the controls and information that actually make sense for it.

Music

Artists, albums, tracks, playlists, listening history, insights, queue and playback.

Movies

Poster-oriented browsing, watch state, continue watching and resume playback.

Manga

Library, reading progress, favourites, categories and a foundation for sources and extensions.

Books

Bookshelf browsing, progress, ratings, favourites, series, sorting and search.

Library

Shared inventory, folder sources, artwork, tags, collections and filesystem identity.

Search

A shared cross-library discovery layer so your collection remains one collection.

Product principles

Quiet software for a noisy collection.

oniDash is deliberately practical. It is not trying to replace your files, hide complexity behind a cloud account, or turn a media library into a social network.

Local-first

Designed around your Windows machine, local folders, local database and local service.

Non-destructive

Index your filesystem without taking ownership of the underlying media.

Specialized

Shared infrastructure without forcing every medium into the same generic interface.

Observable

Scanning and metadata workflows remain visible, editable and recoverable.

Open

A documented architecture built with conventional technologies and developed in the open.

Practical

Built for multiple disks, real folders, imperfect metadata and the realities of personal collections.

Under the hood

Simple architecture. Clear boundaries.

The frontend is React, TypeScript, Vite and Tailwind. The local service is ASP.NET Core with SQLite and Entity Framework Core. Media-specific behavior lives behind catalogue/plugin boundaries.
